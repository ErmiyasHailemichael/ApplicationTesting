# Learning Practice: Black-Box Testing, Part 2

**Application:** North Vacation Booking
Tests are designed from the requirements only. No application code was viewed.

**Price formula used:** `nights x $200 + $50 cleaning fee + (guests over 5) x $25 x nights`

---

## Step 1: Conditions and Actions

### Conditions
1. The check-in date is before the checkout date (dates are valid).
2. The reservation is between 1 and 31 nights.
3. The reservation includes between 1 and 12 guests.
4. Every requested night is available.
5. The reservation includes more than five guests.

### Actions
1. Create the reservation (starts in `Pending`).
2. Calculate the standard price (nights x $200 + $50 cleaning fee).
3. Add the extra guest fee ($25 x guests over five x nights).
4. Raise a `ValueError`.
5. Raise an `UnavailableError`.

---

## Step 2: Decision Table

The full table would have 2^5 = 32 rules. It is collapsed to six rules because once one validity condition fails, the later conditions do not affect the result (`-`).

| Conditions and Actions         | Rule 1 | Rule 2 | Rule 3 | Rule 4 | Rule 5 | Rule 6 |
| ------------------------------ | :----: | :----: | :----: | :----: | :----: | :----: |
| Dates are valid                |   T    |   T    |   F    |   T    |   T    |   T    |
| Number of nights is valid      |   T    |   T    |   -    |   F    |   T    |   T    |
| Number of guests is valid      |   T    |   T    |   -    |   -    |   F    |   T    |
| Requested nights are available |   T    |   T    |   -    |   -    |   -    |   F    |
| More than five guests          |   F    |   T    |   -    |   -    |   -    |   -    |
| **Create reservation**         |   X    |   X    |        |        |        |        |
| **Calculate standard price**   |   X    |   X    |        |        |        |        |
| **Add extra guest fee**        |        |   X    |        |        |        |        |
| **Raise `ValueError`**         |        |        |   X    |   X    |   X    |        |
| **Raise `UnavailableError`**   |        |        |        |        |        |   X    |

**Assumption:** Invalid input (`ValueError`) is checked before availability (`UnavailableError`), since the requirements say invalid information raises `ValueError` and an unavailable reservation raises `UnavailableError`.

## Step 3: Decision Table Test Cases

### TC01 (Rule 1): Valid reservation, no extra guest fee
- **Conditions:** All valid, available, 5 or fewer guests
- **Input:** Check-in Oct 1, checkout Oct 4 (3 nights), 3 guests
- **Expected action:** Create reservation, calculate standard price
- **Expected price:** `$650` (3 x $200 = $600, plus $50 cleaning fee)

### TC02 (Rule 2): Valid reservation with extra guest fee
- **Conditions:** All valid, available, more than five guests
- **Input:** Check-in Oct 1, checkout Oct 4 (3 nights), 8 guests
- **Expected action:** Create reservation, calculate standard price, add extra guest fee
- **Expected price:** `$875` ($600 + $50 + 3 extra guests x $25 x 3 nights = $225)

### TC03 (Rule 3): Check-in date after checkout date
- **Conditions:** Dates are not valid
- **Input:** Check-in Oct 4, checkout Oct 1, 3 guests
- **Expected action:** Reservation is not created
- **Expected exception:** `ValueError`

### TC04 (Rule 4): Too many nights
- **Conditions:** Dates valid, number of nights not valid
- **Input:** Check-in Oct 1, checkout Nov 2 (32 nights), 3 guests
- **Expected action:** Reservation is not created
- **Expected exception:** `ValueError`

### TC05 (Rule 5): Too many guests
- **Conditions:** Dates and nights valid, number of guests not valid
- **Input:** Check-in Oct 1, checkout Oct 4 (3 nights), 13 guests
- **Expected action:** Reservation is not created
- **Expected exception:** `ValueError`

### TC06 (Rule 6): Night not available
- **Conditions:** Input valid, but Oct 2 is already booked
- **Input:** Check-in Oct 1, checkout Oct 4 (3 nights), 2 guests
- **Expected action:** Reservation is not created
- **Expected exception:** `UnavailableError`

### Additional boundary tests (extend Rules 1 and 2)

| ID | Input | Expected price |
| -- | ----- | -------------- |
| TC07 | Oct 1 to Oct 2 (1 night, minimum), 1 guest | `$250` ($200 + $50) |
| TC08 | Oct 1 to Nov 1 (31 nights, maximum), 12 guests | `$11,675` ($6,200 + $50 + 7 x $25 x 31 = $5,425) |
| TC09 | Oct 1 to Oct 2 (1 night), 6 guests (one over five) | `$275` ($200 + $50 + 1 x $25) |

## Step 4: Reservation States and Events

### States
1. `Pending`
2. `Confirmed`
3. `Checked In`
4. `Completed`
5. `Cancelled`

### Events
1. Payment succeeds
2. Payment fails
3. Guest cancels
4. Guest checks in (on the check-in date)
5. Guest checks out (after checkout)

---

## Step 5: State Transition Table

| #  | Current State | Event                                    | Expected State | Expected Result                                      | Type    |
| -- | ------------- | ---------------------------------------- | -------------- | ---------------------------------------------------- | ------- |
| 1  | Pending       | Payment succeeds                         | Confirmed      | The reservation is confirmed.                        | Valid   |
| 2  | Pending       | Payment fails                            | Cancelled      | The reservation is cancelled and dates are released. | Valid   |
| 3  | Pending       | Guest cancels                            | Cancelled      | The reservation is cancelled and dates are released. | Valid   |
| 4  | Confirmed     | Guest cancels                            | Cancelled      | The reservation is cancelled and dates are released. | Valid   |
| 5  | Confirmed     | Guest checks in (on check-in date)       | Checked In     | The guest is checked in.                             | Valid   |
| 6  | Checked In    | Guest checks out (after checkout)        | Completed      | The reservation is completed.                        | Valid   |
| 7  | Cancelled     | Guest attempts to check in               | Cancelled      | An `InvalidStateError` is raised.                    | Invalid |
| 8  | Completed     | Guest attempts to cancel                 | Completed      | An `InvalidStateError` is raised.                    | Invalid |
| 9  | Pending       | Guest attempts to check in               | Pending        | An `InvalidStateError` is raised (must be confirmed first). | Invalid |
| 10 | Checked In    | Guest attempts to cancel                 | Checked In     | An `InvalidStateError` is raised (only pending or confirmed can cancel). | Invalid |
| 11 | Confirmed     | Guest attempts to check in before check-in date | Confirmed | An `InvalidStateError` is raised. *(Assumed from "on its check-in date".)* | Invalid |

### Complete reservation sequence

**ST12:** `Pending` -> payment succeeds -> `Confirmed` -> guest checks in -> `Checked In` -> guest checks out -> `Completed`.
After `Completed`, any further event raises an `InvalidStateError`.

### Cancellation sequence

**ST13:** `Pending` -> payment succeeds -> `Confirmed` -> guest cancels -> `Cancelled` (dates released) -> guest attempts to check in -> stays `Cancelled`, `InvalidStateError` raised.

**Total:** 13 state transition test cases (6 valid, 5 invalid, 2 sequences).
